# Cloudflare 配额优化

用户已批准执行审查发现的优化，并于本会话批准全局限流退避。仅本地实现和验证，不部署、不提交。

## 行为与约束

- 已完成等稳定任务的可见页面轮询由 60 秒降为 5 分钟；运行中维持 5 秒；等待重试按到期时间唤醒，最多 60 秒检查一次。聚焦、重新可见、用户操作和跨日恢复刷新。历史页使用同一策略。
- 活动首次展开才读取；账号切换不复用旧活动，参与后的结果校验保留。
- 执行器签到流水诊断按显式开关开启，默认关闭额外流水请求；任务失败证据仍记录。
- 没有执行任何写操作的失败直接返回供调度退避；已发出写操作的模糊结果保留回查与收益未知语义。
- 等待启动闸门的消息先持久化交回 D1，再 ack，由已有调度重新安排；失败才重投。4 秒启动间隔、32 个在途上限、5 次业务预算、版本及 token 防护不变。空闲调度先查询是否有候选或需要恢复，避免无效更新。
- 全局限流：60 秒内两个不同账号在每日任务接口收到明确 HTTP 429 后，阻止新投递和新启动，至少等待 60 秒并遵守观察到的 Retry-After；已运行任务继续，403、业务文字错误、单账号重复错误不触发。状态持久化至现有 D1，跨实例一致，冷却不增加业务次数。
- 鉴权仅复用没有请求闭包的会话读取配置/实例，不缓存用户或会话结果，不改变退出/删除立即失效。登录插件继续按请求创建。
- 赞助名单采用短期公开缓存，读取失败不缓存。活动详情仅在原有隔离与取消语义下做有界并发（如验证不成立则记录原因）。

## 压力测试结论

不得用全局 auth 实例捕获 execution 或 loginTiming；不得把诊断查询失败影响正常签到；不得跳过已写入后的回查；不得在 D1 交回失败后 ack。全局退避以不同账号且明确 HTTP 状态为条件，并校验实际执行的 lease/version，旧结果不能暂停新任务。

## 验收

对比相同 fixture 下 SQL/消息/上游请求数、稳定页面轮询频率、鉴权 CPU 基准；覆盖并发投递、旧 token、D1 失败、过期 lease、跨日、冷却恢复、注销及多账号隔离。测试使用本地 SQLite、workerd 和 mock，不调用真实短信或活动参与。账单降幅需要部署后的同口径观测，不能由本地耗时直接推算。
